[`node_service.rs:257-273`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-dkg-worker/src/node_service.rs#L257-L273) calls `abort_on_disconnect` after any connection end and then anchors; [`dkg.rs:141-188`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-runtime/src/dkg.rs#L141-L188) transitions a running checkpoint to a chained, encrypted terminal abort with conditional update.

Safety order is visibly preserved: [`lib.rs:392-423`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-dkg-worker/src/lib.rs#L392-L423) commits admission before FROST DKG, seals the share before recording Completed, and commits the reply digest before IPC output; [`lib.rs:326-340`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-dkg-worker/src/lib.rs#L326-L340) refuses any old checkpoint. SIGKILL cannot synchronously mark `aborted`: it leaves `running`, which is deliberately **non-resumable**, not an authorization to restart.

**Limitation:** source-level checks establish neither atomic global conflict finality nor a successful fault rehearsal. In [`relay.rs:353-359`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-dkg-worker/src/relay.rs#L353-L359), the local relay moves to `Complete` immediately after local Finalize; it cannot subsequently promise to detect conflicts that arrive **after** polling stops. ### 2.2 Signing equivocation, durable nonce and abort — source mitigation with a new audit gap

[`signing.rs:341-414`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-dkg-worker/src/signing.rs#L341-L414) waits for all-member activation, then all selected-signer approval; the selected-signer conflict/over-quota checks run **before** deduplication and include already seen slots. On errors *inside the async signing result block*, `record_abort` is attempted. [`SigningSession::begin`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-dkg-worker/src/signing.rs#L191-L220) binds custody, activation and approved intent and calls signer.prepare; [`ControlledSigner::prepare`](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/899e433d057a4d1a0533e2304a2493edb75ad82f/crates/mpc-frost-ed25519/src/lib.rs#L590-L605) reserves the nonce slot *before* generating a commitment, then journals authorization before releasing it.

**New observation S15-L01:** `SigningSession::begin(...)?` at `signing.rs:369-370` is **outside** the `result.map_err(...record_abort...)` at lines 407–413. A failure after `start_deadline` but within `prepare` or outbound setup can therefore return without that outer explicit abort-event path. This is an **audit/terminal-state coverage question**, not demonstrated nonce reuse: the nonce reservation itself is separate and designed to fail closed. Add a targeted fault injection at each Begin substep before claiming "every post-deadline failure is abort-journaled." No currently reviewed test proves the broader invariant end to end. A late conflict after a completed artifact is not guaranteed to be polled; preview claims must describe observation boundaries.

The candidate coordinator Sweettest intentionally reproduces legacy acceptance; it is **not** a repaired coordinator rejection test and is **NOT RUN**. [Migration matrix](https://github.com/ConorTttttt/holochain-threshold-cryptography/blob/2bc9c8d09cfcbeae5fb229eceacd4b949b9ce6b0/docs/sdk/CROSS_APPLICATION_ISOLATION.md) explicitly blocks deployment pending version/DNA compatibility decision.
